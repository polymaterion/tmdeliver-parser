# tm-courier-watch

Мониторит ваш список Telegram-чатов (публичных и приватных, в которых состоит аккаунт юзербота) и присылает объявления о поездках в/из Туркменистана:
кто едет и готов взять документы/посылки, кто ищет попутчика, кто хочет получить посылку.
**Фильтр полностью детерминированный (словари + правила), без ИИ, нейросетей и внешних API.**
Писать автору вы будете вручную — рассылок и автосообщений нет.

Состав: `userbot` (Telethon, отдельный аккаунт) → фильтр → PostgreSQL → `bot` (aiogram, уведомления и управление).
Подробный анализ правил: [docs/ANALYSIS.md](docs/ANALYSIS.md).

## Установка

Нужны Docker и Docker Compose.

1. `cp .env.example .env` и заполните:
   - `POSTGRES_*` — придумайте пароль;
   - `TG_API_ID`, `TG_API_HASH` — на https://my.telegram.org (для **отдельного** аккаунта юзербота);
   - `BOT_TOKEN` — у @BotFather; `ADMIN_IDS` — ваш числовой id (узнать у @userinfobot), несколько — через запятую;
   - `HASH_SALT` — любая случайная строка.
2. Отредактируйте `config/chats.yml`: 20–25 чатов: публичные — по `username`, приватные — по числовому `id` вида `-100…` (инвайт-ссылки `t.me/+…` не поддерживаются). **Аккаунт юзербота должен уже состоять в этих чатах** — сам он никуда не вступает и ничего не ищет.
3. Права на каталог сессии: `mkdir -p secrets && sudo chown 10001 secrets && chmod 700 secrets`.
4. Однократный вход юзербота (код из Telegram, пароль 2FA):
   `docker compose run --rm -it userbot python -m app.userbot.login`
5. Запуск: `docker compose up -d --build`. Миграции БД применяются автоматически при старте.
6. Откройте бота, нажмите /start. Чужие пользователи игнорируются.

## Как пользоваться

Уведомление: категория, маршрут, направление, дата, чат, **причины срабатывания**, текст и кнопки:

```
[👍 Полезно] [👎 Не релевантно]
[👤 Профиль] [💬 Сообщение]
```

«Полезно / Не релевантно» ведут статистику для улучшения фильтра. «Сообщение» — ссылка на исходное сообщение в чате.
«Профиль» — ссылка на автора: `t.me/<username>`, а если username нет — `tg://user?id=<id>` (откроется, если позволяют настройки приватности автора).
Для анонимных админов, каналов, ботов и удалённых аккаунтов кнопка «Профиль» не показывается.

Команды: `/settings` (порог 10–95, вкл/выкл уведомлений, категории, язык) · `/sources` (вкл/выкл чатов) ·
`/add_source @username` или `/add_source -100…` (id приватного чата) · `/stats` · `/export` (CSV находок и оценок для улучшения фильтра; без телефонов отправителей) ·
`/test текст` (проверить фильтр на любом тексте) · `/lang`.
Выгрузка из консоли: `docker compose run --rm bot python -m app.tools.export_feedback /tmp/m.csv`.

## Расширение словарей (без правки кода)

Каталог `rules/` подключён к контейнерам. Файлы:
`cities.json` (города и написания), `lexicons.json` (списки слов: глаголы поездки, предметы, вопросы…),
`keywords.json` (правила: шаблоны, баллы, роли, пояснения ru/tk), `patterns.json` (месяцы и regex дат), `scoring.json` (веса и пороги).
Свои дополнения кладите в `rules/custom/` как `keywords.<имя>.json`, `cities.<имя>.json` и т. п. — они **добавляются** к основным
(одинаковый `id` правила/города переопределяется). Userbot подхватывает изменения сам (≤5 мин), бот — после `docker compose restart bot`.

Синтаксис шаблона: `слово`, `корень*`, `a|b|c`, `{ЛЕКСИКОН}`, `~` (0–3 слова), `~~` (0–6 слов). Слова можно писать на любом
написании (кириллица/латиница/транслит) — они приводятся к единому «скелету»; посмотреть: `python -m app.tools.skeleton "текст"`.
Прогон файла: `python -m app.tools.analyze_file messages.txt` (сообщения через пустую строку).

## Локализация

Все тексты бота — в `locales/*.ftl` (формат Fluent): `ru` (по умолчанию) и `tk`. Новый язык = новый файл `locales/xx.ftl`
с теми же ключами (появится в /lang автоматически). Пояснения к правилам фильтра — поля `desc.ru` / `desc.tk` в `keywords.json`.
Язык выбирается для каждого пользователя бота (по языку Telegram, затем /lang).

## Обновление

`git pull && docker compose up -d --build` (миграции применятся сами). Только словари/переводы: правка файлов + `docker compose restart`.

## Безопасность и приватность

- Токены, API-ключи, сессия юзербота — в `.env` и `./secrets/` (в `.gitignore`), не в коде и не в образе.
- Юзербот игнорирует личные переписки 1:1, читает только сообщения чатов из списка; не пишет в чаты. Для приватных чатов он один раз просматривает список диалогов аккаунта, но запоминает только чаты, указанные в вашем списке.
- Ссылка «Открыть сообщение» для приватного чата (`t.me/c/…`) открывается только у участников этого чата.
- Логи не содержат текста сообщений, токенов и телефонов (маскируются). Для кнопки «Профиль» в БД хранится ссылка на профиль автора (username или id); для дедупликации используется солёный хэш. В `/export` и логи профили не попадают.
- Защита от повторов: уникальность `(chat_id, message_id)`, водяные знаки по чатам, атомарная «заявка» на уведомление (`FOR UPDATE SKIP LOCKED`), дедупликация текстов (14 дней).
- Восстановление: бесконечные ретраи Telethon, экспоненциальная пауза при обрыве, обработка FloodWait, докачка пропущенного по водяным знакам.

## Тесты

`pip install -r requirements.txt && pytest` — тесты фильтра на синтетических примерах (положительные/отрицательные, даты, маршруты, расширение словарей, дедуп, паритет переводов).

## Ограничения

- Сообщение без названия города/страны Туркменистана (например, «Есть кто летит?») не распознаётся — контекста чата фильтр не видит.
- Номера без кода страны не определяются как туркменские.
- Telegram не позволяет читать чат, не состоя в нём: вступайте аккаунтом вручную.
